## 0. 핵심 결정 — 거리는 GPS가 아니라 계기판에서 읽는다

| | GPS로 거리 계산 | 계기판(Odometer API)에서 읽기 |
|---|---|---|
| 정확도 | 터널·지하주차장에서 끊기고, 계기판 숫자와 안 맞음 | 계기판 숫자 그대로 |
| 국세청 양식 | 양식은 '주행 전·후 **계기판의 거리**'를 적게 되어 있음 → 추정치를 적게 됨 | 양식 칸에 그대로 들어감 |
| 위치정보 | 이동 경로 = 개인위치정보 수집 → 위치정보법 신고·동의가 오히려 필요 | 위치를 전혀 안 씀 |
| 경쟁 | 휴대폰 운행일지 앱들이 이미 이 방식 | **차 안에서만 가능한 방식 = 우리 차별점** |

- 결론: **1차 버전은 위치정보를 하나도 모으지 않는다.** 그래서 위치기반서비스 신고도 필요 없다.
- 위치 얘기가 나왔던 건 '방문처'(어디 갔는지) 때문. 그런데 국세청 양식에서 방문처는 필수 칸이 아니라 비고 칸이다. → 1차는 **말로 메모**("거래처 김사장 미팅")로 채우고, 내비 목적지 자동 입력은 2차에 동의를 받아 넣는다.

# 1부. 접수양식 초안

## 1. 앱 한 줄 소개
시동만 걸고 다니면, 계기판 거리를 그대로 읽어 국세청 업무용 승용차 운행기록부를 자동으로 채워 주는 사장님 차 비서.

## 2. 기획 배경
- 업무용 승용차 비용(감가상각·리스료·유류비·보험료 등)은 **운행기록부를 쓰지 않으면 1년에 1,500만 원까지만** 비용으로 인정된다(법인, 성실신고확인대상 개인사업자 등). [택스워치 2024](https://www.taxwatch.co.kr/article/tax/2024/04/11/0001)
- 양식은 운행마다 **주행 전·후 계기판 거리**, 업무 사용 거리(출퇴근 / 일반 업무)를 적게 되어 있다. 바쁜 사장님·영업직은 매번 계기판을 보고 적지 못해 몰아서 '대충' 쓰거나 포기한다.
- 휴대폰 운행일지 앱은 GPS로 거리를 추정해서 계기판 숫자와 맞지 않고, 폰 블루투스·배터리·권한에 따라 기록이 빠진다.
- Pleos가 처음 들어간 차는 그랜저 — 법인·사업자 수요가 많은 차다. 차 안에 이미 있는 숫자를 그대로 쓰면 이 불편이 사라진다.

## 3. 주요 기능 및 차량 특화 요소
1. **자동 운행 기록** — 출발하면 그 순간의 계기판 거리, 주차하면 도착 계기판 거리와 시간을 저장. 아무것도 누르지 않아도 운행 1건이 생긴다.
2. **말 한마디 분류** — 주차하면 "이번 운행, 업무로 기록할까요?" → "응, 거래처 미팅" 한마디로 업무/출퇴근/개인 구분과 비고 메모 끝. 운전 중엔 아무것도 묻지 않는다.
3. **알아서 제안** — 평일 아침 첫 운행은 '출퇴근', 자주 가는 시간대 패턴은 '업무'로 미리 골라 둔다. 사람은 맞으면 넘기기만.
4. **월말 장부** — 미분류 운행을 한 화면에서 몰아 분류. 과세기간 총 주행거리·업무 사용 거리·**업무사용비율 자동 계산**.
5. **국세청 양식 엑셀** — 양식 그대로 엑셀·PDF로 내보내 세무사에게 링크 하나로 공유.
6. **유류비 참고** — 차가 아는 실제 연비 × 주행거리로 운행별 유류비를 추정(참고용).

차량 특화 요소: 계기판 누적거리·트립 거리/시간, 연비·연료량, 좌석 착석, 문 열림을 차량 SDK로 직접 읽는다. 휴대폰으로는 계기판 숫자를 얻을 수 없다.

## 4. 주요 사용 시나리오
**김 대표(52세, 인테리어 업체, 그랜저)의 하루**
1. 08:10 집에서 출발 → 앱이 계기판 12,340km 기록. 김 대표는 아무것도 안 함.
2. 08:45 사무실 주차 → 화면에 "출퇴근으로 기록했어요(12,358km, 18km)" 한 줄. 맞으니 그냥 내림.
3. 14:00 현장 갔다 옴 → 주차하며 "업무, ○○아파트 현장" 한마디.
4. 토요일 마트 → "개인".
5. 월말 → 휴대폰으로 온 알림 "이번 달 업무 사용 82%, 세무사님께 보낼까요?" → [보내기].
6. 3월 법인세 신고 → 세무사는 1년 치 양식 엑셀을 받아서 그대로 첨부.

## 5. 개발 계획 (SDK·API 사용 계획)
- **차 앱**: Android(Kotlin) · Pleos Connect SDK
  - Vehicle SDK — Odometer(`getCurrentDistanceDriven`, 트립 거리·시간), Fuel(`getFuelPercent`, 연비), EvBattery(전기차 전비), Seat(`getCurrentSeatOccupancy`, 운전자 착석), Door(문 열림), Speed(AAOS `PERF_VEHICLE_SPEED`)
  - Gleo AI App Schema — 음성 함수 3개: ① 이번 운행 분류 ② 메모 남기기 ③ 이번 달 요약 듣기
  - STT/TTS SDK — 메모 받아쓰기, 요약 읽어 주기
  - 주행 중에는 화면 조작 없음. 분류 카드는 주차 상태에서만 표시
- **관리 웹**: Flutter Web + Firebase — 월말 분류, 엑셀/PDF 출력, 세무사 공유 링크
- **데이터**: 차 안 로컬 DB에 먼저 저장 → 통신될 때 서버로. 위치 좌표는 저장하지 않음
- **에뮬레이터 시연**: Pleos Connect 에뮬레이터 + Virtual Console로 계기판 값·문·착석을 바꿔 가며 하루 운행을 재현

## 6. 기대효과 및 발전 가능성
- **타깃**: 업무용 차를 쓰는 법인 대표·임원, 개인사업자(성실신고확인대상 등), 외근 영업직. 1차는 그랜저·아반떼 오너 중 사업자.
- **가치**: 운행기록부 작성 시간 0분, 1,500만 원 한도에 걸려 잃던 비용 인정을 되찾음, 세무 증빙의 신뢰도(계기판 원값).
- **예상 MAU (예시 산식)**: Pleos 탑재 차량 수 × 업무용 비율 × 설치율. 업무 운행마다 자동으로 쓰이고 매달 정산이 있어 **재방문(Retention)이 구조적으로 높다** — 월말 정산 알림이 매달 다시 부른다.
- **수익(예시)**: 차 1대 월 구독(예: 3,900원), 세무사 사무실 묶음 판매(고객사 차량 일괄), 렌트·리스사 제휴.
- **확장**: ① 내비 목적지 자동 방문처(동의) ② 장기렌트 약정거리 초과 미리 알림 ③ 법인 여러 대·여러 운전자 관리(시트 위치로 운전자 추정) ④ 세무 프로그램 연동 ⑤ 연말 '우리 차 1년 결산' 화면

# 2부. 개발 기획 (내부용)

## A. 1차 버전(공모전 제출) 범위
| 포함 | 뺌(2차) |
|---|---|
| 자동 운행 기록(계기판 시작·끝, 시간) | 위치·방문처 자동 입력 |
| 주차 후 분류 카드 + 음성 분류·메모 | 여러 운전자 구분 |
| 자동 제안(출퇴근 시간대 규칙) | 장기렌트 약정거리 |
| 월간 목록·미분류 몰아 분류 | 세무 프로그램 연동, 결제 |
| 국세청 양식 엑셀 출력, 공유 링크 | 법인 여러 대 관리 화면 |
| 유류비 참고 계산 | |

## B. 화면
- 차: ① 홈(이번 달 운행 수·업무비율) ② 주차 후 분류 카드 ③ 운행 목록 ④ 설정(차 이름, 사용자, 유가)
- 관리 웹: ① 로그인 ② 월별 장부 표 ③ 엑셀·PDF 내보내기 ④ 세무사 공유 링크

## C. 운행 1건 판단 규칙 (초안)
- 시작: 속도 > 0이 처음 나온 순간의 계기판 값
- 끝: 속도 0 + 운전석 문 열림(또는 운전석 착석 해제) 순간의 계기판 값
- 신호대기·잠깐 정차(문 안 열림)는 같은 운행으로 이어 붙임
- 앱이 꺼져 있다 켜지면: 직전 끝 값과 지금 값의 차이를 '기록 누락 구간'으로 표시해 사람이 확인

## D. 데이터 (운행 1건)
날짜·요일, 사용자, 출발/도착 시각, 주행 전 계기판(km), 주행 후 계기판(km), 주행거리, 구분(출퇴근/업무/개인/미분류), 메모(비고), 추정 유류비
